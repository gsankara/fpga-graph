# Design P — one graph, several FPGAs

Design C bakes a whole graph into one card. **Design P bakes one partition of
the vertex set**, so a graph spans several cards and the hop becomes a
distributed operation. The point is not capacity — ring50 is 50 vertices and
fits a U280 ten thousand times over — it is **latency**: every BFS hop costs
one exchange between the cards, and that exchange is what the OCT, NRP and
FABRIC experiments each measure in a different place.

## The decomposition

Partition by the **target** vertex. FPGA *k* owns a vertex subset `V_k` and
holds the in-adjacency wiring of exactly those vertices. One hop on card *k*
computes, for `v` in `V_k` only:

```
res[v] = s[v] | OR over u in in_adj[v] : s[u]        (latch mode)
res[v] =        OR over u in in_adj[v] : s[u]        (pulse mode)
```

and leaves every bit outside `V_k` clear. Because the `V_k` are disjoint and
cover `V`, the partials have disjoint support and

```
full_step(s)  ==  OR over k of partial_step_k(s)
```

holds **exactly** — no boundary correction, no approximation. The combine is a
single OR of N-bit words.

`sim/verify_partition.py` proves it: **185,360 comparisons** against
`graphgen/reference.py`, over exhaustive vertex subsets up to pairs plus 400
random ones, every hop count 0–27, both latch and pulse, both split modes, zero
mismatches.

## What each card needs, and what it does not

A card needs the **whole** state to evaluate its rows, because a neighbour of a
local vertex may live anywhere. So one hop is:

```
broadcast s (N bits) -> every card
each card emits its partial (N bits, only its own vertices set)
OR the partials -> s for the next hop
```

**One exchange per hop.** The exchange volume is N bits whatever the split, so
the cut does not change communication cost in this scheme. The cut is reported
anyway, as the figure of merit for a later boundary-only optimisation — sending
only the bits the peer's rows actually read.

## Exactly one hop per invocation — not negotiable

A second stage inside a partitioned kernel would read stage 1's state for
*neighbour* vertices, which this card does not compute and which therefore read
as 0. A 2-stage partitioned kernel is **silently wrong**. It is the
missing-exchange bug, and `sim/verify_partition.py` shows 50 % of its test cases
(89 % under an interleaved split) expose it — but only after a ~2 h link spent
finding out. So `gen_hls_partitioned.py --stages` is pinned at 1 and refuses
anything else, and the host drives multi-hop with one exchange per hop.

## The demo graph: ring50

`examples/ring50.edges` — 50 vertices, 50 undirected edges, generated by the
repo's own `make_graph.py --nodes 50 --degree 2`.

| | whole graph | per FPGA (2 partitions) |
|---|---|---|
| vertices | 50 | **25** |
| in-adjacency terms | 100 | **50** |
| eccentricity | 25 | — |
| estimated LUT | — | ~35 |

Per card that is *n/2* vertices and *n* adjacency terms, which is the sizing
this experiment was specified at. Eccentricity 25 gives a long hop series —
up to 25 exchanges from a single seed — which is what makes a small graph
enough to measure a per-hop cost cleanly.

Two splits, same volume, very different cut:

| split | cut terms (of 100) | note |
|---|---|---|
| `block` | **4** | two contiguous arcs; only the two seams cross |
| `interleave` | **100** | every edge crosses |

Both are correct. The pair brackets the locality question on an identical
graph, and the interleaved split is much better at exposing an orchestration
bug, which is why the negative controls use it.

## Why it should close timing

Every design-C bitstream closed within **16 picoseconds** of failing, and that
margin comes from the U280 static shell, not the kernel — even a 28-line vector
add only just cleared it. Design P's kernels are ~35 LUT and one hop deep,
which is the easiest case this shell will ever see. Read the verdict from
`_xl/reports/link/imp/impl_1_hw_bb_locked_timing_summary_routed.rpt` and record
WNS/WHS as numbers regardless: `vpp_link.log` does not reliably carry it.

## Files

| file | role |
|---|---|
| `graphgen/partition.py` | partition map, distributed step, cut statistics |
| `graphgen/gen_hls_partitioned.py` | graph + partition -> HLS kernel, header, metadata |
| `sim/verify_partition.py` | proves the decomposition against `reference.py` |
| `sim/check_wiring.py` | validates emitted wiring with no compiler — the pre-link gate |
| `sim/compare_part.py` | signs off csim or hardware against `reference.py` |
| `sim/tb_part.cpp` | csim harness, one partition |
| `host/part_query.cpp` | several cards in **one box** — exchange via host memory |
| `host/part_agent.cpp` | one card **per node** — exchange over TCP, per-hop RTT |
| `scripts/build_part.sh` | builds every partition; `TARGET=u280` or `TARGET=u55c` |
| `scripts/u280.cfg`, `scripts/u55c.cfg` | HBM bank pinning, identical on both cards |

## Targets

| target | cards | exchange crosses | built on |
|---|---|---|---|
| OCT | 2 × U280, one node | host memory | `csg-fpga-compile0` |
| NRP | 2 × U55C | host memory | `csg-fpga-compile3` |
| FABRIC | 2 × U280, two sites | wide-area link | `csg-fpga-compile0` |

The U55C is **HBM-only** — no DDR — so its bundles must be pinned to HBM banks
or the link fails. `u280.cfg` pins the same banks even though the U280 would
place without it: the cross-card latency comparison is only clean if the memory
path is identical on both.

## Order of operations

```bash
# 1. prove the decomposition (seconds, no hardware)
python3 sim/verify_partition.py examples/ring50.edges

# 2. generate + gate the wiring (seconds, no compiler)
python3 graphgen/gen_hls_partitioned.py examples/ring50.edges --part 0 --nparts 2 --name ring50
python3 graphgen/gen_hls_partitioned.py examples/ring50.edges --part 1 --nparts 2 --name ring50
python3 sim/check_wiring.py build/ring50_p0of2_block build/ring50_p1of2_block

# 3. build both bitstreams on the right Coder box
TARGET=u280 bash scripts/build_part.sh ring50 2 block     # csg-fpga-compile0
TARGET=u55c bash scripts/build_part.sh ring50 2 block     # csg-fpga-compile3

# 4. run and sign off
python3 sim/compare_part.py --graph examples/ring50.edges \
    --exe "./part_query 50 1 p0.xclbin p1.xclbin"
```

Step 2 gates step 3 inside `build_part.sh`: a generator bug costs a second
there instead of two hours of place-and-route.
